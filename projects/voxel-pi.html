VoxelPi

An open-source reimplementation of the VoxelSpace engine — the terrain renderer behind Comanche (1992) — in Python and Pygame, tuned to stay playable on a Raspberry Pi.

How VoxelSpace works

There is no 3D geometry in this renderer at all — no triangles, no mesh, no z-buffer. The world is two bitmaps of the same size: a height map and a colour map. To draw a frame, the engine walks outward from the camera in steps, and at each step samples a horizontal line across the maps. Each sample becomes one vertical line on screen, its height set by the height map and its colour taken from the colour map.

Drawing back to front, with nearer columns painted over farther ones, produces correct occlusion for free. That is the whole trick, and it is why the technique ran at speed on 1992 hardware without a floating-point unit — and why it maps neatly onto a Raspberry Pi three decades later.

The Python and Pygame implementation here is my own; the algorithm follows s-macke's VoxelSpace write-up, which reconstructs the original renderer.

Making Python keep up

The catch is that a per-column loop in Python is exactly the shape of code Python is worst at. The work here is less about the algorithm — which is short — and more about how much detail can be traded away before it stops looking right: sampling step size, render distance and column width are all adjustable, and the graphics settings exist so the same code can be dialled between a desktop and a Pi.
